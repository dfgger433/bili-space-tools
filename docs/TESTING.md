# 测试说明（主分支单脚本）

主分支交付一个脚本：`dist/B站空间页增强.user.js`，内含动态翻页 / 图文翻页 / 统一行高三个模块。
每个模块都可以在油猴菜单里单独开关；单独脚本保留在各自维护分支。

## 安装

1. 油猴管理面板导入 `dist/B站空间页增强.user.js`，启用。
2. 打开对应页面（动态 / 图文），刷新一次。
3. 点油猴图标确认菜单项存在：
   - `动态翻页：开/关`
   - `图文翻页：开/关`
   - `统一行高：开/关`
   - `行高裁剪阈值：27%（0=关闭）`（统一行高模块开启时出现）
   - `图片压缩：开/关`（图文模块开启时）

## 测试矩阵

| # | 操作 | 预期 |
|---|---|---|
| 1 | 动态页，默认设置 | 每页 12 条；原生分页条；第 2 页即时打开；滚到底仍预取下一页 |
| 2 | 动态页，菜单关闭“动态翻页” | 分页条消失，恢复原生动态列表；再开启后重新分页 |
| 3 | 图文页，关闭“统一行高” | 只保留 02 分页；分页条 1 个；卡片瀑布流 |
| 4 | 图文页，关闭“图文翻页” | 分页条消失；统一行高切到原生克隆模式，所有已加载图文等高 |
| 5 | 图文页，两模块都开 | 分页 + 等高行同时生效；分页条只有 1 个；翻页后新页仍等高 |
| 6 | 图文页，滚动到底 | 原生自动加载更多；统一行高自动覆盖新加载内容（不是固定 20 条） |
| 7 | 同一行封面/文字 | 超出比例 ≤ 27%：行高 = 最高卡片，保留原始内容；> 27%：行高 = 平均，超过平均的卡片用 B 站默认封面裁剪（标题保留）；不再强行展开文字 |
| 8 | 行高裁剪阈值菜单 | 点“行高裁剪阈值”输入 0/27/40：0=全部原始；27=默认；40=部分恢复原始；刷新后保持 |
| 9 | 特别高的竖图 | 超过平均值的卡片按 B 站默认封面裁剪，行高 = 该行平均值；不再把整行拉到最高 |
| 10 | 菜单开关后刷新 | 开关状态保持 |
| 11 | 图片压缩开关 | 开 = `@640w.webp`；关 = 原图；刷新后保持 |
| 12 | 缩小/放大窗口 / 切 tab | 列数/数据变化后重新排版，不报错 |
| 13 | 控制台 | `window.BILI_TOOLS.all.state/settings` 正常；`row.state.mode` 为 `native` 或 `bt`；无 `[bili-tools]` 报错 |

## 自动测试

```powershell
npm test
npm run test:e2e
npm run test:e2e:opus      # 含三个模块开关的 e2e
npm run test:e2e:real
npm run test:visual
npm run test:live:opus     # 只开图文翻页
npm run test:live:row      # 只开统一行高
npm run test:live:combined # 图文翻页 + 统一行高
```

真实站点冒烟已通过：只开统一行高 20 条 4 行、滚到底 40 条 8 行；图文翻页 + 统一行高两页都等高且分页条只有 1 个。

## 单独脚本

单独脚本在维护分支上构建，不影响主分支：

| 分支 | 内容 |
|---|---|
| `fix/dynamic-page-12` | 动态翻页 |
| `feat/opus-pagination` | 图文翻页 |
| `feat/opus-uniform-row` | 图文统一行高 |

## 反馈

异常时 F12 控制台过滤 `[bili-tools]`，附上：
- 页面、模块开关状态；
- `window.BILI_TOOLS.all.state`；
- 对应模块的 `state`（统一行高含 `lastError`）；
- 报错截图。
